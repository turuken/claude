# Canvaセリフデザイン強調編集スキル

Canvaで作られた「あ「〇〇」幹「△△」」のようなセリフ形式の一枚絵/ショート動画素材に対して、
セリフの可読性向上や、特定のセリフ(「マジかーっ」等の驚き表現)を目立たせる編集を行うための手順。

## なぜこの手順が必要か

Canva MCPの`format_text`操作には`font_family`/`fontRef`を変更するパラメータが存在しない。
つまり書体(フォントの種類)そのものをAPI経由で変えることはできない制約がある。
これを知らずに「フォントを変更しました」と報告すると、実際には見た目が変わっておらず
ユーザーの信頼を損なう。この制約を最初に正直に伝え、代替手段(色・太さ・斜体・サイズ変更、
または手動変更用のフォント名提案)を示すのがこのスキルの核心。

また、対象デザインのURLが `https://www.canva.com/d/xxxxx` という短縮リンク形式の場合、
`resolve-shortlink`や`read-design`にそのまま渡すと解決できないことが多い(307エラー等)。
その場合はセリフのキーワードで`search-designs`を使い、内容を照合して特定する。

## 参照テンプレート(新規デザイン作成時)

ユーザーから「新しい台本でこのやり方で作って」のように**新規作成**を依頼された場合は、
以下のデザインをベーステンプレートとして使う(ユーザー指定の基準デザイン):

- タイトル:【外国人に感謝】
- design_id: `DAHUUdPmrJE`
- 編集URL: `https://www.canva.com/design/DAHUUdPmrJE/V6nr_rV3-F2qKyb86NRTdg/edit`

手順:
1. `copy-design`(`design_id: "DAHUUdPmrJE"`)で複製し、新しいデザインを作成する。
2. 複製後のデザインに対して`read-design`(`open_transaction: true`)で構造を読み取り、
   各セリフ要素の`locator_id`を確認する。
3. `replace_text`または`find_and_replace_text`で、新しい台本のセリフ内容に差し替える。
   レイアウト・座標・既存のフォーマットはテンプレートのものをそのまま活かす。
4. 差し替え後、本スキルの3〜4節の手順(フォント可読性向上・驚きセリフの強調)を
   同様に適用する。

このテンプレート情報が古くなっている、または対象デザインが削除されている場合は、
ユーザーに新しい参照リンクを確認する。

## 手順(既存デザインの編集を依頼された場合)

### 1. 対象デザインの特定

1. まず `read-design` にユーザーから渡されたURLをそのまま渡してみる。
2. 失敗する場合(`resolve-shortlink`も307エラーになりがち)、`search-designs`で
   ユーザーが挙げたセリフの一部(例:「マジかーっ」)やデザインタイトルのキーワードを検索する。
3. 該当しそうなデザインが複数見つかったら、各候補を`read-design`で読み、
   `design_content`のセリフ全文を比較する。1件に絞れない場合は、
   **AskUserQuestionで候補のタイトルと内容の要約を提示し、ユーザーに選んでもらう**。
   ここを推測で決め打ちしない — 別の投稿の個人情報を誤って編集するリスクがある。
   `updated_at`(更新日時)が新しいことだけを根拠に1件へ絞り込むのは避ける
   — 依頼内容と実際のセリフ・書式が一致しているかという内容面の証拠を優先し、
   それでも決め手がなければ必ずユーザーに確認する。

### 2. デザイン内容の読み取り

`read-design`を`open_transaction: true`、`filter.fields: ["design_metadata", "page_metadata",
"design_content", "thumbnails"]`で呼び、セリフ各要素の`locator_id`とテキスト内容、
現在の`formatting`(fontSize, fontWeight, color等)を把握する。

このとき、同じ座標(top/left)に複数のテキスト要素が重なっていることがある
(タイムド・リビール型の動画用デザインでよくある構造)。重なりに気づいたら、
サムネイル上で狙った要素が見えていなくても、返ってきた`document`のJSON上で
該当`locator_id`のテキスト内容が一致していれば編集対象として問題ない
(サムネイルは静止画レンダリングのため、重なった別要素が手前に表示されているだけ)。

### 3. 「セリフのフォントを読みやすく」への対応

**書体自体はAPIで変更できないことを最初に明示する。** その上で、次のいずれかをユーザーに選んでもらう:

- 太さ・サイズ・行間の調整で読みやすさを底上げする(自動適用可能)
- 手動変更用に、日本語で可読性の高いフォント名を提案するだけにする

候補フォント例(手動提案用):

| フォント名 | 特徴 |
|---|---|
| Noto Sans JP (Regular〜Medium) | 癖がなく視認性が高い定番 |
| Zen角ゴシック New | 適度な丸み・太さで親しみやすい |
| M PLUS 1p / Rounded M PLUS | 丸みがありSNS/ショート動画向き |
| キアロ(Canva内蔵) | くっきりした線でスマホでも視認性が良い |

どちらを選んでも、ユーザーの意向を確認してから実行する(黙って太字化だけ進めない)。

### 4. 驚きセリフ(例:「マジかーっ」)の強調

対象テキスト要素の`locator_id`に対し、`edit-design`の`format_text`操作で以下を組み合わせる:

- `color`: 赤系(例 `#FF3B30`)や黄色系など、警告・驚きを連想させる色
- `font_weight`: `bold`
- `font_style`: `italic`
- `font_size`: 元のサイズの1.3〜1.5倍程度

適用例:
```json
{
  "type": "format_text",
  "locator_id": "PBxxxx-LByyyy",
  "formatting": {
    "color": "#FF3B30",
    "font_weight": "bold",
    "font_style": "italic",
    "font_size": 125
  }
}
```

**適用後は必ず検証してからコミットする:**
1. `edit-design`のレスポンスに含まれる`document`のJSONを確認し、
   狙った`locator_id`の`formatting`が意図通りに変わっているかを照合する。
2. サムネイルでも見えていれば見た目を確認する(重なり要素で見えない場合は1.の照合で代替可)。
3. 問題なければ`finalize: "commit"`で確定保存する。
4. 別の色・演出を試したくなった場合や、確認だけで終わる場合は`finalize: "cancel"`で
   トランザクションを破棄し、無駄な編集を残さない。

### 5. 音声追加の要望が来た場合

**Canva MCPには音声(オーディオ)要素をデザインに挿入する操作が存在しない**
(`insert_fill`は`asset_type: image | video`のみ対応)。この制約を先に伝える。

音声クリップ自体はhiggsfield_aiの`generate_audio`で生成できる:

1. `list_voices`で声質の候補を確認し、ユーザーに近いイメージを選んでもらう
   (AskUserQuestionで「コミカルな男性/女性」「落ち着いた声」等の選択肢を提示)。
2. `generate_audio`を`get_cost: true`で先に呼び、必要クレジットを確認する。
3. `balance`で現在の残高を確認し、不足していればユーザーに
   「購入する/見送る」を確認する(勝手に課金方向へ進めない)。
4. 生成できても、Canvaへの組み込みはこのAPIでは不可能なので、
   「素材→オーディオ→アップロード」で手動追加が必要であることを案内する。

### 6. 進め方の原則

- 各分岐点(対象デザインが複数候補ある、フォント変更の方針、音声生成の声質、
  クレジット不足時の対応)で**AskUserQuestionを使い、決め打ちしない**。
- 「フォントを変更しました」のように、実際には変わっていない/変えられない内容を
  変更済みであるかのように報告しない。できないことは明確に「できない」と伝える。
- 文字装飾やテキスト差し替えなど、実際に自動適用できる操作を行った後は、
  必ずcommit前に反映結果(JSONまたはサムネイル)を確認する。
